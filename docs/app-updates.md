# 用户更新接口

从 0.5.2 开始，Windows 和 Android 在侧栏底部提供“关于与更新”，登录页也保留同一入口。应用读取系统报告的真实安装版本，用户主动点击“检查更新”后才访问公开版本清单，不发送账号、会话或工作台数据。能查看更新内容、版本日期和安装包大小，并打开对应平台的下载链接。

固定接口为 `https://raw.githubusercontent.com/Z-FLY-FADED/atlas-personal-workbench/main/updates/latest.json`，结构定义见 `updates/schema.json`。`schemaVersion` 当前为 1，包含版本、构建号、渠道、更新说明、发布页及 Windows/Android 的下载地址、文件大小与 SHA-256。接口不需要 Supabase 认证或新增数据库表，后续可以迁移到自己的 HTTPS 服务；构建时可用 `UPDATE_MANIFEST_URL` 指定接口，`UPDATE_REPOSITORY` 指定受信任的 GitHub 仓库，两者均为公开配置。

版本按语义版本比较；同版本时比较构建号，旧版本不触发降级。请求有 12 秒超时和 64 KiB 响应限制。格式错误、未知接口版本、非 HTTPS 或非受信任仓库地址均不作为有效更新。网络异常可重试，并保留打开发布页的入口。清单中的 SHA-256 为发布核验和以后扩展应用内下载器预留；当前由外部浏览器下载，应用不宣称已经验证浏览器下载文件的哈希。

## 后续发布步骤

递增 `apps/atlas/pubspec.yaml` 的版本和构建号，更新对应的 `docs/release-版本.md` 及下载说明，完成检查、测试、双平台构建并运行 `scripts/write-native-build-manifest.mjs`。运行 `scripts/prepare-downloads.ps1` 后，分发目录会额外生成 `update.json`，自动填入两个安装包的真实大小和 SHA-256。默认渠道为 `preview`；正式版使用 `-Channel stable`。

将该目录的全部附件上传到对应的 GitHub Release，核对附件并公开发布。随后运行 `scripts/publish-update-manifest.ps1`：脚本会确认 Release 已公开、两个平台的附件及 `update.json` 与本地一致，再更新 `updates/latest.json`。把这份清单提交并推送到 `main` 后，旧客户端下一次手动检查即可看到更新。未公开或缺少安装包的版本不能提前进入更新接口。无需重新部署数据库或让用户重新注册。

维护端脚本优先使用已登录的 GitHub CLI 核验发布，避免匿名 GitHub API 的额度限制；未安装 CLI 时尝试公开 API。客户端直接读取静态清单，不需要 GitHub 登录或令牌。

Windows 目前下载完整 ZIP，关闭旧程序后解压新版运行；Android 下载同应用 ID、同签名的 APK 覆盖安装，保留原应用。安装过程由用户按系统提示完成，暂不静默替换程序。Windows 后续可在此接口上增加经过签名验证的安装器，Android 也可继续扩展受系统控制的安装流程。

0.5.1 及更早版本没有检查更新入口，需要先手动安装当前版本（0.6.0）。账号、Android 应用 ID、长期签名和原有 Windows 登录存储继续兼容。此功能的自动测试不等同于 Android 真机安装或双设备同步验收。

## 数据保护

已登录用户通过“下载更新”或“打开下载页”更新时，先等待保存与专注记录完成，读取最新云端数据，再将当前账号的全部业务集合保存为本机加密快照。写入后解密回读并核对字节摘要、备份校验和及记录数，成功后才继续下载。失败时停止本次下载，不清理旧备份、不修改云端记录。可用“导出更新备份”另存可恢复的 JSON，之后通过“数据与恢复”导入。

自动备份位于系统应用支持目录的 `update-backups/` 下，按云项目和账号隔离；随机加密密钥由系统安全存储保管，不与安装目录一起替换。Windows 安全存储操作使用队列和文件锁，避免会话刷新与备份密钥更新互相覆盖。重要内容应另存独立备份，避免设备故障或主动卸载带来的风险。

版本清单包含 `dataCompatibility`：数据格式版本、云项目来源指纹、Android 应用 ID 和签名指纹、Windows 产品与公司标识。准备分发包时读取并核对实际 APK 签名、包名和版本；客户端和发布脚本也核对兼容标识，阻止无意间切换云项目、换签名或改数据目录。迁移数据源需要单独设计迁移方案，不通过普通更新隐式切换。
