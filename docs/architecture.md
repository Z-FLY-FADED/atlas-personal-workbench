# ATLAS 架构

2026-10-12 完成框架重构。应用继续使用 React、TypeScript、Vinext、Cloudflare D1 和 Electron。页面地址、API 地址、数据库结构、用户数据和原有功能保持兼容。

## 模块边界

```text
app/page.tsx
    └─ shell/WorkspaceApplication
         ├─ shell/components       导航、全局搜索、状态栏
         ├─ useWorkspaceController 功能装配和跨功能连接
         └─ WorkspaceOutlet        按需加载各功能视图
                └─ features/<功能>/views
                     ├─ components  页面和弹窗
                     ├─ hooks       状态、派生值和操作
                     └─ domain      分类、算法、日期与内容规则

shared/api ── HTTP ── api/<地址>/route.ts ── server/<功能>
                          适配请求             查询和持久化

contracts                 共享类型、数据格式和可在浏览器使用的常量
styles                    保留既有层叠顺序的样式模块
db + migrations           数据库定义和迁移
desktop + scripts         桌面外壳和本机启动
```

`WorkspaceApplication` 装配导航、视图和弹窗，不实现具体业务。`useWorkspaceController` 连接各功能 Hook；状态 Hook 始终在工作台外壳中挂载，切换页面后仍保留查询结果和编辑状态。视图和弹窗收到所需字段的 `Pick<WorkspaceController, ...>`，不直接依赖其他页面组件的内部状态。

## 请求与服务端

`shared/api/httpClient.ts` 管理超时、取消和响应错误。写请求继续只发送一次；读取和修改状态由 `useWorkspaceIO` 统一反馈。存储草稿、下载和文档解析独立于页面组件。

`app/api` 只声明路由策略并把请求交给 `server`。工作台服务拆分为 `queries.ts`、`commands.ts`、`serialization.ts` 和 `webSources.ts`；查询、修改、恢复、定时任务和来源采集仍使用原有鉴权规则。岗位种子内容与请求处理也分别维护。

浏览器与服务端共同需要的备份类型、大小限制和校验函数放在 `contracts/archive.ts`。数据库访问、备份恢复和回收站修改仅属于 `server/data`，不会通过备份界面进入浏览器代码。

## 按需加载与交互

`WorkspaceOutlet` 按页面加载视图。弹窗只有在打开时才请求代码；共享弹窗 Hook 等待弹窗 DOM 挂载，再安装焦点管理、Tab 循环、Escape 关闭和草稿恢复，关闭时解除监听。页面异常边界提供重新加载入口，保留侧栏导航。

URL、历史导航、本地主题和最近浏览记录继续由会话 Hook 协调。跨功能操作，例如笔记转任务、项目打开关联资料，经过控制器连接功能操作。

## 样式

`globals.css` 只保留 Tailwind 与 16 个有序样式模块的导入。原有补充样式仍在 `layout.tsx` 中按原顺序加载。拆分不重新排列覆盖关系，避免改变桌面、手机、主题和知识阅读页的呈现。

## 离线与公开来源（2026-10-13）

`contracts/runtime.ts` 定义三种运行模式。`server/runtime` 在既有 `workspace_settings` 表中按用户保存模式，无需数据库迁移。默认 `public` 模式使用规则和公开来源，关闭模型执行；`offline` 停止新外网采集及模型执行；`ai` 才允许主动模型查询，定时模型执行还需要独立的 `automaticAI` 开关。服务端检查模式，防止只禁用按钮却仍能调用模型。暂停的计划不会占用可执行计划的调度名额。

基础业务继续通过本机服务访问本机 D1/SQLite，包括任务、项目、笔记、提醒、知识分类、教材、语言学习、求职记录和统计周报。本机服务运行时，断开互联网不影响这些读写。远程部署或手机与服务器的连接完全中断时，尚不能把数据库修改保存到服务器；周报与收录表单的本机草稿仍保留，统计周报可导出。该模式没有引入会重复提交写操作的自动队列。

`server/research` 只按用户范围读取已保存资料和内置教材，返回关键词匹配与原文摘录，不把个人记录交给外部模型。公开 URL 提取只发送 URL，使用正文筛选、逐次重定向检查和 2MB 响应上限；明确选择“网址”收录才会抓取，普通笔记内的链接不会触发抓取。RSS/Atom 仍由既有行业采集器处理，不依赖 AI。

招聘、行情和市场目录通过 `server/runtime/publicSources.ts` 适配器执行模式检查与持久化缓存；原采集器保持独立。缓存按用户隔离，最多保存 12 份，每份不超过 500KB。断网或来源失败时读取历史缓存，并附保存时间；历史行情关闭实时标识与当前信号。没有缓存时仅展示本机目录或明确的不可用状态，不生成报价。网页原文也可缓存并在离线检索时使用。

模式面板位于数据恢复和 AI 页面。周报默认使用 `reviewDraft` 的真实统计，只有用户主动加载可选模型并执行整理时才进入 AI 流程。模式变更会清除外壳中岗位与行情的旧加载状态，让下次显示采用新模式。

## 扩展约束

1. 新增功能先在 `contracts` 定义数据接口，再在对应 `features` 目录实现规则、状态和视图。
2. 页面入口、视图和通用组件不得运行 SQL 或引入服务端模块。纯类型依赖使用 `import type`。
3. 纯业务规则不依赖 React；服务端不依赖页面组件。跨功能连接由外壳负责，避免运行时循环依赖。
4. 新 API 在 `server` 实现业务，`api` 仅适配 HTTP。数据库变更通过新迁移完成。
5. 新样式放入相应样式模块，并确认其在全局层叠中的顺序。
6. 检查类型、ESLint、业务测试、架构测试和生产构建；涉及交互时在隔离数据副本中验证。

目前保留统一工作台状态的装配机制和既有样式覆盖关系，便于本轮验证行为兼容。后续如果出现独立页面路由或细粒度状态订阅需求，可以在现有功能边界上继续演进。
